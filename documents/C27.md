C27 hoàn thiện giao diện trên khung C04, sử dụng C17/C09/C13 và giao diện C14
đã có. C23 kiểm thử contract backend; C27 bổ sung bằng chứng browser.
Không thay thuật toán xếp hạng, quyền nguồn, Search, Reader hoặc contract.

- `web/src/pages/RecommendPage.tsx`: sở thích đã lưu, Similar tạm, bộ lọc,
  k mặc định 5 (đổi được 1–10 theo SPEC 13.2), loading/result/empty/error,
  ẩn/thử lại, chuyển snapshot chủ động và vô hiệu hóa request cũ.
- `web/src/services/recommendationClient.ts`: gọi API qua `apiClient`, dùng
  alias từ type OpenAPI hiện có; kiểm tra snapshot và thứ tự rank của phản hồi.
  Không tự tính score, sắp xếp hoặc tạo reason_text.
- `web/src/services/preferenceSelection.ts`: kiểm tra tối đa ba work khác nhau,
  giữ đúng ấn bản, nhận Similar làm sở thích khi bấm nút, đối chiếu ID/work
  khi chuyển dataset. Không suy eligibility từ metadata phía trình duyệt.
- `web/src/services/tabStorage.ts`: mở rộng tùy chọn schema_version=1 trong
  `ai_library_v1`: recommendation_filters, recommendation_k, preference_books

  này vẫn đọc được. Không lưu kết quả, spinner hoặc request đang chạy.
- `web/src/pages/DetailPage.tsx`: điểm nối P3 — nút chọn/bỏ sở thích,
  Sách tương tự và Xem gợi ý. Catalog/BookCard vẫn mở trang chi tiết như trước.
  Nếu P3 bổ sung chọn trực tiếp trên card, gọi `selectPreference(book, snapshot)`
  và cập nhật số seed; không thêm một cách kiểm tra work hoặc kho state khác.
- `web/src/App.tsx`: remount theo URL để vô hiệu hóa chế độ/snapshot cũ;
  thông báo active snapshot mới, giữ layout và router chung.
- `web/src/styles/index.css`: khoảng cách, chip seed, lý do và cột nút gợi ý;
  dùng màu, font, focus và breakpoint hiện có.

## Quy tắc trạng thái và API

Chưa chọn sách: hướng dẫn chọn, không gọi Recommend ngẫu nhiên. Thêm cùng work
báo đã có, không thay ấn bản; seed thứ tư bị chặn. Đổi seed/filter/k bỏ kết quả
cũ nhưng giữ exclude. Ẩn lưu ID trước rồi gửi lại; lỗi không hoàn tác tập ẩn.
Bỏ ẩn tất cả xóa exclude và gửi lại khi có seed. Xóa lựa chọn chỉ xóa seed,
exclude, cache/xung đột liên quan và kết quả; giữ query, filters và list_state.

`POST /api/v1/recommend` nhận seed/exclude/filter/k/snapshot hiện tại.
`/recommendations?similar=<book_id>&snapshot_id=<snapshot>` là chế độ tạm:
gọi GET Similar, không ghi đè seed/filter/exclude đã lưu. Tham số filter/k/hidden
của chế độ này nằm trên URL để Back/Forward/reload giữ đúng đầu vào.
GET Similar không có exclude trong C03; sau khi ẩn, chế độ tạm dùng POST Recommend
với seed tạm và exclude tạm tương đương, vẫn không thay sở thích đã lưu.

Chỉ nút **Dùng làm sở thích** thay seed đã lưu thành sách tạm. Khi đó bỏ khỏi
exclude những ấn bản cùng work với seed mới, giữ các work bị ẩn còn lại.
Không nhận sách ở snapshot khác vào sở thích đang có; yêu cầu chuyển dữ liệu
chủ động trước. Cache tên/work chỉ dùng trong snapshot của nó.

HTTP 200 no_candidates là trạng thái rỗng; ít hơn k hiển thị số thật. Lỗi 422
giữ đầu vào, hiện message/field. Similar thiếu ID hiện 404 theo contract/review
đã ghi ở C17/C23; snapshot không còn phục vụ có hướng dẫn riêng và nút tải mới.
503/mất mạng/timeout có Thử lại. Không fallback mock khi API thật lỗi.

Mỗi thao tác có mã lượt UI riêng; đổi đầu vào, chế độ hoặc rời trang tăng mã
và abort request. Cả success/error cũ bị loại dù fetch không tuân AbortSignal.
Deadline 12 giây kết thúc loading độc lập với abort. Không so với request_id server.

Health không tự chuyển snapshot của phiên. **Tải dữ liệu mới** đọc snapshot
active, tải catalog theo phân trang (20 là kích thước trang, không phải giới hạn
danh mục), đối chiếu toàn bộ seed/exclude. ID mất, work đổi, không có cache work
cũ để đối chiếu hoặc xung đột work được giữ và báo để người đọc sửa; không tự
xóa seed. Cách đối chiếu hiện tại đọc toàn bộ catalog khi người đọc chủ động
chuyển dữ liệu; với catalog rất lớn có thể cần API kiểm tra ID theo batch sau này.
Storage hỏng có thông báo chung; bị chặn thì giữ trong bộ nhớ đến reload.
Demo bật chủ động dùng kho demo có sẵn, tách khỏi phiên API thật.

## Chạy với API thật

Node 22, Python dự án `.venv/Scripts/python.exe` (máy kiểm chứng: 3.12.14).
Cài backend theo README và model/cache P4; không encode lại E5. Từ gốc repo:

```powershell
$env:PYTHONPATH = 'api;pipeline'
$env:SMARTLIBAI_DEMO_SNAPSHOT = (Resolve-Path 'data/demo/p4-w03-c38-reviewed-r8-20261122/snapshot/p4-w03-c38-reviewed-r8-20261122').Path
$env:MODEL_ROOT = (Resolve-Path models).Path
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
.venv/Scripts/python.exe -B -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Đây là snapshot P4 phục vụ thực, không phải HTTP mock dù tên biến có DEMO.
Để dùng kho active triển khai, bỏ SMARTLIBAI_DEMO_SNAPSHOT và dùng SNAPSHOT_ROOT,
CONTROL_ROOT theo README gốc. Luôn kiểm tra `/api/v1/health`: recommend_ready=true
và snapshot đúng phiên; snapshot Reader mới hơn nhưng chỉ có SQLite không thay
được snapshot FAISS. Terminal khác:

```powershell
cd web
npm ci # Khi chưa có node_modules đúng lockfile
$env:VITE_DEMO_MODE = 'false'
npm run dev -- --host 127.0.0.1 --port 3000 --strictPort
```

Mở `http://127.0.0.1:3000/`, chọn sách từ chi tiết, vào Gợi ý.
Proxy có sẵn trong `web/vite.config.ts`, component không hardcode host API.
`npm run dev:demo` chỉ minh họa, có thông báo rõ; không chứng minh FAISS.

có script lint/test riêng. Browser dùng Python Playwright và Edge đã có trên máy
